# Save Diffs & Patches Implementation Plan (v2)

This blueprint details the extension of the `ArtifactProcessor` in 
`src/vybz/artifact.py` to support the extraction and persistence of Unified 
Diffs generated by the `diff-generation` skill.

## 1. Goal
Enable the `/save` command to intelligently detect `diff` or `patch` code 
blocks within an Agent's response and save them as `.diff` files. This allows 
developers to apply changes via `patch -p1` without manual copy-pasting.

## 2. Architectural Changes

### 2.1 Target Module: `src/vybz/artifact.py`
The parsing logic now resides in `ArtifactProcessor.parse`. We will modify this 
method to implement a **Priority Chain** for artifact detection:

1.  **Priority 1 (Documents):** Check for `type: Design|Blueprint|Intent` in 
    YAML Frontmatter. (Existing Logic).
2.  **Priority 2 (Patches):** Check for code blocks tagged `diff` or `patch`.
    *   *Reason:* If no Design doc is present, the Diff is likely the intended 
        output.
3.  **Priority 3 (Fallback):** Raw text fallback.

## 3. Module Specification: `src/vybz/artifact.py`

### 3.1 Method Update: `ArtifactProcessor.parse`

The logic must iterate through the Markdown tokens to find specific block types.

#### Logic Flow
1.  **Tokenize:** `tokens = self.md.parse(text)`
2.  **Pass 1 (YAML):** Iterate tokens looking for `fence` with `---` start.
    *   If found, parse as Document (Design/Blueprint).
    *   *Return immediately* (Documents take precedence).
3.  **Pass 2 (Diffs):** Iterate tokens looking for `fence` with info string 
    `diff` or `patch`.
    *   If found, select this block as `candidate_content`.
    *   **Filename Extraction:**
        *   Regex: `^\+\+\+ b/(.+)$` (Multi-line mode).
        *   *Strategy:* Find the *first* file header in the diff.
        *   *Sanitization:* Replace path separators `/` with `-` to flatten the 
            structure.
            *   Example: `src/vybz/repl.py` -> `src-vybz-repl.py.diff`.
        *   *Fallback:* If no header found, use `patch-{timestamp}.diff`.
    *   **Directory:** Hardcoded to `output` (or `patches` if preferred, but 
        `output` is current standard).
    *   *Return* `Artifact(type="Diff", ...)`
4.  **Pass 3 (Fallback):** If no blocks found, use raw text.

### 3.2 Filename Heuristics
Diffs often contain multiple files.
*   **Single File Diff:** Name it after the file being patched (e.g., 
    `src-vybz-agent.py.diff`).
*   **Multi File Diff:** If the regex finds multiple `+++ b/` headers, fallback 
    to a generic name `multi-patch-{timestamp}.diff` OR name it after the 
    first file found. *Decision:* Name after the first file found, as it is 
    usually the primary target.

## 4. Verification Strategy

### 4.1 Unit Tests (`tests/vybz/test_artifact.py`)
We will add specific test cases to the existing test suite.

#### Test: `test_parse_diff_block`
*   **Input:** A Markdown string containing a fenced block tagged `diff` with 
    standard Unified Diff content (`--- a/foo`, `+++ b/foo`).
*   **Assert:**
    *   `artifact.type == "Diff"`
    *   `artifact.filename == "foo.diff"`
    *   `artifact.directory == "output"`

#### Test: `test_parse_priority_yaml_over_diff`
*   **Input:** A response containing BOTH a Design Doc (YAML) and a Diff block.
*   **Assert:** The artifact returned is the Design Doc.

### 4.2 Manual Verification
1.  **Agent:** `vybz junior-dev`
2.  **Prompt:** "Refactor `src/vybz/ui.py` to change the success color to 
    blue. Output a Unified Diff."
3.  **Action:** `/save`
4.  **Expectation:** `Saved Diff to output/src-vybz-ui.py.diff`.

## 5. Execution Steps
1.  **Update `ArtifactProcessor.parse`:** Implement the secondary pass for 
    diff tokens.
2.  **Implement Regex:** Add the `+++ b/` extraction logic.
3.  **Update Tests:** Add the new test cases to `tests/vybz/test_artifact.py`.
4.  **Verify:** Run `pytest`.
