# Save Diffs & Patches Implementation Plan

This blueprint details the extension of the `/save` command in 
`src/vybz/repl.py` to support the extraction and persistence of Unified Diffs 
generated by the `diff-generation` skill.

## 1. Goal
Enable the `/save` command to intelligently detect `diff` or `patch` code 
blocks within an Agent's response and save them as `.diff` files in the 
`output/` directory. This allows developers to apply changes via `git apply` or
`patch -p1` without manual copy-pasting.

## 2. Architectural Changes

### 2.1 Parsing Logic Update (`src/vybz/repl.py`)
The `_parse_artifact` method currently only looks for YAML Frontmatter to 
identify Designs, Blueprints, or Intents. It must be refactored into a 
**Priority Chain**:

1.  **Priority 1 (Documents):** Check for `type: Design|Blueprint|Intent` in YAML.
    *   *Reason:* These are primary architectural artifacts.
2.  **Priority 2 (Patches):** Check for code blocks tagged `diff` or `patch`.
    *   *Reason:* Implementation details.
3.  **Priority 3 (Fallback):** Raw text fallback.

### 2.2 Filename Heuristics
Unlike Design docs which use H1 titles (`# Title`), Diffs use file headers 
(`+++ b/path/to/file`). The parser must extract these headers to generate 
meaningful filenames.

## 3. Module Specification: `src/vybz/repl.py`

### Method: `_parse_artifact`

#### Strategy 2: Diff Extraction
*   **Trigger:** Token type is `fence` AND info string is `diff` or `patch`.
*   **Regex Extraction:**
    *   Pattern: `^\+\+\+ b/(.+)$` (Multi-line).
    *   *Note:* The `b/` prefix is standard in git-style unified diffs.
*   **Filename Logic:**
    *   **Single Match:** If exactly one file header is found:
        *   Extract path (e.g., `src/vybz/repl.py`).
        *   **Sanitize:** Replace `/` and `\` with `-`.
        *   Result: `src-vybz-repl.py.diff`.
    *   **Multi Match:** If > 1 header is found:
        *   Result: `patch-{HHMMSS}.diff`.
    *   **No Match:** If block is tagged `diff` but lacks headers:
        *   Result: `diff-{HHMMSS}.diff`.
*   **Directory:** Hardcoded to `output` (to prevent polluting source tree with unapplied patches).

## 4. Security Constraints
*   **Path Traversal:** The filename generation MUST flatten the path.
    *   Input: `+++ b/../../etc/passwd`
    *   Sanitized: `..-..-etc-passwd.diff`
    *   *Goal:* Prevent the `/save` command from writing outside the `output/` directory.

## 5. Verification Strategy

### Test Case 1: Single File Refactor
1.  **Input:** Agent outputs a diff for `src/vybz/agent.py`.
2.  **Action:** `/save`.
3.  **Expectation:** File saved to `output/src-vybz-agent.py.diff`.

### Test Case 2: Multi-File Patch
1.  **Input:** Agent outputs a single code block containing diffs for `foo.py` and `bar.py`.
2.  **Action:** `/save`.
3.  **Expectation:** File saved to `output/patch-{timestamp}.diff`.

### Test Case 3: Priority
1.  **Input:** Agent outputs a Design Doc (YAML) AND a Diff in the same response.
2.  **Action:** `/save`.
3.  **Expectation:** The Design Doc is saved (Priority 1). The Diff is ignored unless the Design Doc block is missing.
